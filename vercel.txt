--------------------------------------------------------------------------------
 3. WHAT THIS VARIABLE IS FOR
--------------------------------------------------------------------------------
   VITE_API_URL
       Base URL of the kanban API, consumed at src/lib/api.ts:3-4 as
           export const API_BASE =
               import.meta.env.VITE_API_URL || 'http://localhost:4000'

       If it is unset the build still succeeds and the frontend still deploys.
       It only fails at runtime, in the browser, as
           "Cannot reach the API at http://localhost:4000"

       That is the single most common Vercel misconfiguration for this project.

   NO OTHER VARS
       The frontend has exactly one env var. There is deliberately no
       VITE_JWT_SECRET or similar. All auth is server-side; the browser only
       ever holds an httpOnly cookie. Never put a secret in a VITE_ prefixed
       var, because Vite inlines those into the public JS bundle.


--------------------------------------------------------------------------------
 4. BUILD-TIME, NOT RUNTIME  (this is the gotcha)
--------------------------------------------------------------------------------
   Any VITE_ prefixed variable is inlined into the bundle AT BUILD TIME.
   Changing VITE_API_URL in the dashboard does nothing until you redeploy.

   Project -> Deployments -> redeploy the latest commit (or push a no-op commit
   to force a fresh build).

   Verify the deployed bundle actually has the right URL:
       curl -s https://notes-dusky-eta-79.vercel.app/ | grep -o '/assets/[^"]*\.js'
       curl -s https://notes-dusky-eta-79.vercel.app/assets/<that-file>.js \
            | grep -o 'https://[a-z0-9.-]*onrender\.com'

   If that grep prints nothing, the old bundle is still being served.


--------------------------------------------------------------------------------
 5. PRODUCTION ENVIRONMENTS
--------------------------------------------------------------------------------
   Vercel scopes variables per environment: Production / Preview / Development.
   A value set only under "Preview" will NOT apply to the production URL above.
   Add it under Production.
